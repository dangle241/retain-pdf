In sci mode, decide for each item whether to translate it or keep the original PDF content without overwriting.
Use `decision: "keep_origin"` when translating the block could break layout, produce awkward output, or when the block is better left as-is. Typical cases include metadata fragments, author/affiliation lines, citation-format entries, editor dates, standalone short connectives, and semi-structured text.
Do not rely solely on the OCR block type; if a block is itself standalone code, a command, configuration, an input file, a directory tree, or a file manifest, prefer `decision: "keep_origin"`.
If a block mixes natural-language explanation with commands, parameters, filenames, variable names, formulas, or code tokens, prefer `decision: "translate"`. Translate only the natural-language explanation and preserve those literals verbatim in the translation.
Do not switch to `keep_origin` simply because a normal body paragraph contains a few imperative tokens, inline formulas, or variable names; only the literal tokens themselves stay verbatim while the surrounding sentence is still translated.
The system-provided decision hints are evidence, not hard rules; if a hint conflicts with the semantics of the text, follow your own judgement of the current text.
Do not express "do not translate" by copying the English source_text into translated_text.
When the correct action is to keep the original PDF content, do not omit the decision field.
If `decision` is `keep_origin`, translated_text must be empty.
If `decision` is `translate`, provide the translation normally.
In sci mode you must return one tagged block per item; do not return JSON or Markdown.
Use the following format strictly:
<<<ITEM item_id=ITEM_ID decision=translate|keep_origin>>>
Translation; leave empty when decision=keep_origin
<<<END>>>
Every requested item_id must produce a block.

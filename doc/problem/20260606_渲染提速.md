## Background

RetainPDF The current most critical time-consuming point in the rendering phase is not Typst Not text rendering itself, but the source. PDF Cleaning and preprocessing, especially the "physically delete original text" path.

For general editable PDFIdeal path:

1. According to OCR / normalized document's bbox find the original text region to delete.
2. Use pikepdf to parse and rewrite page content stream.
3. Remove text rendering inside hit region. token。
4. Then by Typst Render translation.

The value of this path is cleaner output, no reliance on white block overlay, and also reduces browser overhead. PDF Background text residue issue in rendering. But in large... PDF、Form XObject For scenes with many vector paths and complex page objects, the old implementation is extremely slow.

Optimization objective: reduce algorithmic complexity and redundancy from the ground up, not add rules. IO, bring 500-page PDF physical deletion latency within acceptable range. Current target: mostly normal PDF complete source within tens of seconds. PDF cleanup. Complex pages use explicit fallback without slowing down all pages.

### 1. Replace full rect scan with spatial index

Core files:

- `backend/scripts/services/rendering/source_cleanup/planning/spatial_index.py`

Add `RectOverlapIndex`: sort page rects by y direction, then use `bisect_right` to find potentially intersecting candidate ranges, then do x-direction quick reject.

It solves this type of problem:

```text
item bbox -> Whether and unsafe vector rect Intersection
target rect -> whether it intersects with drawing rect
```

Current implementation is very lightweight:

```text
RectOverlapIndex
rects: rectangles sorted by y0
    y0_sorted: Extracted separately. y0 Array, used for bisect

overlaps_any(target_rect)
1. Use target_rect.y1 to binary search in y0_sorted prefix to get possible intersecting prefix.
2. Skip rectangles with y1 < target.y0.
3. Use x0/x1 for fast exclusion.
    4. Calculate actual intersection area last.
```

Old logic: per item Scan All rectNew logic first pass y Interval pruning: check only few possible intersections. rect。

Underlying complexity approaches:

```text

```

```text

```

Here `local_candidates` is typically far less than full page rect count.

## Design principles

### Deprecated. job/page rule patching

Incomplete deletion not solved by adding more:

```text
If it is page x
if bbox looks like a formula
if some block id
```

Such rules conflict with each other and also slow down large... PDFThe current direction is to PDF Break pages into stable underlying facts:

- Does the page have Form XObject。
- Page content stream size.
- Which pages? OCR bbox Needs deletion.
- Physical deletion invalid for which candidate regions?
- Which pages should be accessed directly? cover fallback。

Strategy consumes only these facts; does not directly depend on specifics. job Exception.

### Acknowledge boundaries for complex pages.

pikepdf page-level content stream rewrite is suitable for deleting text in page flow. But if text is hidden inside Form XObject, only a `Do` appears in page flow, forcing deletion at page level is unreliable.

Therefore identify complex pages early to avoid heavy expansion. For undeletable pages, retain clear metadata, and then by cover fallback Or background rendering fallback.

### Prioritize indexing for all rectangle issues.

A lot of the logic in render cleanup is essentially... rect overlapAdd feature only when required. ponytail: skip now, add when user explicitly requests it. `A x B` Double-layer full scan, but should first ask:

# rust_api Coupling and Boundary Research

Date:2026-06-15

Goal: find `backend/rust_api` Current most coupling-prone points causing repeated patches, responsibility conflicts, and hard-to-extend evolution. This doc only records current code evidence and split directions; no one-shot refactoring required.

## Current baseline

Target layering defined in existing architecture documentation:

```text
app -> routes -> application services -> internal services -> job_runner / ocr_provider
```

Existing hard access control:

```bash
python3 backend/rust_api/scripts/check_architecture.py
```

Current check results:

```text
rust_api architecture check passed
```

Interim conclusion:

- Hard access control passed.
- `routes / services / job_runner / ocr_provider / db / storage_paths / job_events` These main production areas have converged to `models::api` / `models::domain` / `models::request` narrow facade。
- Filter out. `models/**` Self-implementation and `api_tests/**` Post-build, production source lacks top-level. `use crate::models::{...}` Passthrough import.
- Remaining top-level `crate::models` Self-references primarily occur in `models/input/**`、`models/job/**`、`models/view/**` Internal. Model module implementation detail. No longer represents outer boundary penetration.
- Subsequent sections retain historical issues, completed closures, and soft coupling points still worth splitting later.

## 1. Download API also generates derived artifacts.

Representative file:

- `backend/rust_api/src/services/jobs/downloads/previews.rs`
- `backend/rust_api/src/services/jobs/downloads/side_by_side.rs`
- `backend/rust_api/src/services/jobs/downloads/pdf.rs`

Current status:

- `downloads/previews.rs` Handles pre-download business logic and is embedded. Python Generate cover, thumbnail, page preview.
- `downloads/side_by_side.rs` Responsible for download API; also directly invokes. Python Script generates side-by-side comparison. PDF。
- `downloads/pdf.rs` calls `qpdf` to linearize.

Problem:

- `download API` Originally should lean HTTP File export, but now it's become "File Export". + artifact Derived Builder + External process orchestration.
- If more derived artifacts are added later, e.g., comparisons PDFBilingual, watermarked PDFReader preview cache.`downloads/*` Continues to bloat.
- Cache strategies, locks, andmtime Judgment, Temporary Files rename Will recur.

Suggested boundaries

```text
routes/download_response
  -> services/jobs/downloads       Only decide what to download.
  -> services/derived_artifacts    Generates/Cache-derived artifacts
-> Python/qpdf/PyMuPDF calls
```

Priority: High.

Recommended first step:

- Create `services/derived_artifacts`.
- Push `side_by_side`, `preview/cover/thumbnail`, `linearize` down into 'Generation and Caching'.
- `downloads/*` Call only `ensure_*_artifact(...) -> PathBuf`。

Current progress status:

- `side_by_side.rs` is responsible for original text/side-by-side original and translation PDF generation.
  - Not here assemble `FileDownload`nor decide HTTP Respond.
- Already. `services/jobs/downloads.rs` Harvest Ledger facade：
- `downloads/previews.rs` is responsible for cover, thumbnail, page preview download decision.
- `downloads/artifact_deps.rs` converts job query deps into derived artifact deps.
- `downloads.rs` No longer parses source directly. Use AST if needed. / Translated PDF path, and no longer directly depends on derived artifact Generate module.

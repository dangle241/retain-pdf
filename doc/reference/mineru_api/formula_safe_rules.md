# MinerU Formula security fix rules

This rule applies only to MinerU / UniMERNet type formula OCR output raw latex-ish text.

Goal not "make all formulas prettiest", but:

- Only make low-risk, structured, explainable fixes.
- Avoid global string replacement breaking complex formulas.
- Make Typst / mitex render stably

## Background

MinerU Formula output is essentially generated by the formula recognition model. LaTeX sequence, not PDF Native specification LaTeX。

Common features:

- Space between control word and curly brace:`\mathrm { C H }`
- Subscript superscript separated by spaces.`x _ { i , j }`
- Digits are split in the middle.`1 . 2 7`
- Local style command mixin:`\bf { g }`

## Allow corrections

Keep these rules. Low risk, clear semantics.

- `\mathrm { C H } -> \mathrm{CH}`
- `a _ { b } -> a_{b}`
- `a ^ { b } -> a^{b}`
- `a _ 2 -> a_2`
- `a ^ 2 -> a^2`
- Tighten number internal spacing:`1 . 2 7 -> 1.27`
- `\textsuperscript{...} -> ^{...}`
- Few explicit. OCR Noise repair, e.g. `\mathrm { e V } -> \mathrm{eV}`

## Disable auto-correction.

These rules prohibit global string replacement:

- Global `"{ -> ("`、`"} -> )"`
- Global " _ {" -> "_("
- Global " ^ {" -> "^("
- Mass-delete curly braces via regex.
- Direct rewrite if syntax boundary unconfirmed. `\frac`、`\sqrt`、`\left...\right`
- Guess complex formula structure by length or character set.

## Complex structure handling principles

For the following structures, only perform structural processing and bracket-level balancing:

- `\frac{...}{...}`
- `\sqrt{...}`
- `\left ... \right`
- `x_{i,j}`
- `E_{g}^{dir}`
- `\Delta G_{H^*}`
- `\mathbf{v}_{t+1}`

Principles:

- Tighten first `_` / `^` Atomic binding
- Recursively process group contents.
- Do not aggressively rewrite unknown groups

## Project boundaries

Facts accepted:

- MinerU Output not final LaTeX
- Complex formulas: under-revise rather than over-revise.
- If complex structures are renderable, prioritize keeping them as is.
- On render failure, prioritize. selective sanitize, do not aggressively rewrite on the main path

## Current strategy

Code should follow:

- `normalizer.py` Only apply low-risk whitelist-based hardening.
- `typst_formula_renderer.py` No global brace replacement.
- Complex script structures recursively processed via balanced parentheses.
- All new rules must have regression tests before deployment.

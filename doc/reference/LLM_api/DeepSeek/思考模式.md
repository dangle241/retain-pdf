Thinking mode
DeepSeek Model supports thinking mode: before outputting the final answer, it outputs a chain-of-thought to improve accuracy.

Thinking Mode Toggle and Intensity Control
Control parameters (OpenAI format)    Control parameters (Anthropic format)
Reasoning mode switch(1)	{"thinking": {"type": "enabled/disabled"}}
Reasoning effort control(2)(3)	{"reasoning_effort": "high/max"}	{"output_config": {"effort": "high/max"}}
(1) Default thinking switch is enabled
(2) In thinking mode, default for normal requests effort is high; for some complex Agent class requests (e.g. Claude Code, OpenCode), effort auto-set to max
(3) In thinking mode, for compatibility, low, medium map to high, xhigh maps to max

You are using OpenAI SDK to set thinking parameters, need to put thinking parameters in extra_body:

response = client.chat.completions.create(
  model="deepseek-v4-pro",
  # ...
  reasoning_effort="high",
  extra_body={"thinking": {"type": "enabled"}}
)

Input/Output Parameters
Thinking mode not supported. temperature、top_p、presence_penalty、frequency_penalty Parameters. Note: for compatibility with existing software, setting parameters will not error, but will not take effect.

In thinking mode, chain-of-thought content passes through reasoning_content parameter return, and content at same level. In subsequent turn concatenations, may optionally return reasoning_content to API:

Between two user messages, if the model does not make a tool call, then the intermediate assistant's reasoning_content does not need context concatenation; passing it in subsequent turns will be ignored by API. See multi-turn dialogue concatenation.
Between two user messages, if the model performed a tool call, then the intermediate assistant's reasoning_content must participate in context concatenation, and must be returned to API in all subsequent user interaction rounds. See Tool Use for details.
Multi-turn dialogue concatenation
During each round of dialogue, the model outputs chain-of-thought content (reasoning_content) and the final answer (content) If no tool call, previous rounds' chain-of-thought content not appended to context in next round, as shown below:

Tool Call
DeepSeek Model reasoning mode supports tool calling. Before final output, may perform multiple rounds of reasoning and tool calls to improve quality. Calling pattern shown below:


Note: Unlike thinking-mode rounds without tool calls, tool-call rounds must fully return reasoning_content to API in all subsequent requests.

If your code does not return correctly. reasoning_content，API Returns 400 Error. Correct return method: refer to sample code below.

Sample code
Below is a simple example of tool-calling in thinking mode:

import os
import json
from openai import OpenAI
from datetime import datetime

# The definition of the tools
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_date",
            "description": "Get the current date",
            "parameters": { "type": "object", "properties": {} },
        }
    },
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Get weather of a location, the user should supply the location and date.",
            "parameters": {
                "type": "object",
                "properties": {
                    "location": { "type": "string", "description": "The city name" },
                    "date": { "type": "string", "description": "The date in format YYYY-mm-dd" },
                },
                "required": ["location", "date"]
            },
        }
    },
]

# The mocked version of the tool calls
def get_date_mock():
    return datetime.now().strftime("%Y-%m-%d")

def get_weather_mock(location, date):
    return "Cloudy 7~13°C"

TOOL_CALL_MAP = {
    "get_date": get_date_mock,
    "get_weather": get_weather_mock
}

def run_turn(turn, messages):
    sub_turn = 1
    while True:
        response = client.chat.completions.create(
            model='deepseek-v4-pro',
            messages=messages,
            tools=tools,
            reasoning_effort="high",
            extra_body={ "thinking": { "type": "enabled" } },
        )
        messages.append(response.choices[0].message)
        reasoning_content = response.choices[0].message.reasoning_content
        content = response.choices[0].message.content
        tool_calls = response.choices[0].message.tool_calls
        print(f"Turn {turn}.{sub_turn}\n{reasoning_content=}\n{content=}\n{tool_calls=}")
        # If there is no tool calls, then the model should get a final answer and we need to stop the loop
        if tool_calls is None:
            break
        for tool in tool_calls:
            tool_function = TOOL_CALL_MAP[tool.function.name]
            tool_result = tool_function(**json.loads(tool.function.arguments))
            print(f"tool result for {tool.function.name}: {tool_result}\n")
            messages.append({
                "role": "tool",
                "tool_call_id": tool.id,
                "content": tool_result,
            })
        sub_turn += 1
    print()

client = OpenAI(
    api_key=os.environ.get('DEEPSEEK_API_KEY'),
    base_url=os.environ.get('DEEPSEEK_BASE_URL'),
)

# The user starts a question
turn = 1
messages = [{
    "role": "user",
    "content": "How's the weather in Hangzhou Tomorrow"
}]
run_turn(turn, messages)

# The user starts a new question
turn = 2
messages.append({
    "role": "user",
    "content": "How's the weather in Guangzhou Tomorrow"
})
run_turn(turn, messages)

In Turn 1, each sub-request carries the Turn-produced reasoning_content to API, thus allowing the model to continue its previous thinking. response.choices[0].message carries all required assistant message fields, including content, reasoning_content, tool_calls; use msg = f"{msg}" append to messages end:

messages.append(response.choices[0].message)

This line of code is equivalent to:

messages.append({
    'role': 'assistant',
    'content': response.choices[0].message.content,
    'reasoning_content': response.choices[0].message.reasoning_content,
    'tool_calls': response.choices[0].message.tool_calls,
})

and in Turn 2 request, we still carry Turn1-generated reasoning_content to API.

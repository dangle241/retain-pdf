# Concurrency and batching

in the translation request, `workers` and `batch_size` are not equal to simple "simultaneous send". N requests each with M "items". Backend will schedule based on item types, risks, and provider state.

## Request Fields

```json
{
  "translation": {
    "workers": 100,
    "batch_size": 1
  }
}
```

## Actual scheduling

The translation phase will first take the to-be-translated item Divide into several categories:

- `batched_fast`: Low-risk body, actionable. batch Merge.
- single_fast: normal single-item request.
- `single_slow`: Complex formulas, heavy processing, or high risk item。

`workers` Split into these queues, not a single thread pool.

## Concurrency ≠ parallelism. Context switches, lock contention, cache thrashing add overhead. Amdahl’s Law limits speedup by serial fraction.

- provider Side adaptive concurrency, real inflight HTTP Request may be lower `workers`。
- 429、5xxTimeout triggers backoff and retry.
- `single_slow` Independent worker Upper bound. Complexity. item Won't eat all. worker。
- Results apply and partial flush are digested serially by main flow.
- tail retry Probably in main. batch Append work after completion.

## Diagnostic Fields

Translation diagnostics focus on:

- `configured_workers`
- `configured_batch_size`
- `effective_batch_size_translation`
- `translation_queue_split`
  - `batched_fast_batches`
  - `single_fast_batches`
  - `single_slow_batches`
  - `batched_fast_workers`
  - `single_fast_workers`
  - `single_slow_workers`
- `concurrency_observed.peak_inflight_translation_requests`
- `concurrency_observed.peak_inflight_all_llm_requests`
- `adaptive_concurrency.current_limit`
- `result_apply.apply_elapsed_ms`
- `result_apply.max_result_drain_batch`
- `result_flush.flush_elapsed_ms`
- `result_flush.max_flush_pages`
- `tail_retry.tail_retry_items`
- `tail_retry.tail_retry_elapsed_ms`
- `request_counts.timeout_attempts`

## Frontend rules

- Normal UI may expose only `workers`。
- `batch_size` Better as an advanced option.
- Do not promise in UI that workers=100 means 100 items per second.

# Query task details

## Endpoint

```http
GET /api/v1/jobs/{job_id}
```

Obtain current task snapshot. Page first screen: prioritize this API call, then integrate. events。

## Recommended read fields

```json
{
  "job_id": "20260616120000-abcdef",
  "status": "running",
  "display_stage": "translation",
  "stage": "translating",
  "substage": "translation_batches",
  "lane": "main",
"stage_detail": "Translating batch 789 / 5216",
  "progress": {
    "unit": "batch",
    "current": 789,
    "total": 5216,
    "percent": 15.1
  },
  "background_stages": [
    {
      "display_stage": "render",
      "stage": "rendering",
      "substage": "render_prewarm",
      "lane": "background",
      "progress": {
        "unit": "step",
        "current": 2,
        "total": 3
      }
    }
  ]
}
```

Field description:

- `status`: job status, such as `queued`、`running`、`succeeded`、`failed`、`canceled`。
- `display_stage`: Frontend displays major stages; only interpret by convention as `ocr | translation | render | done`。
- `stage`: Backend internal stage name.
- `substage`: Machine-readable substage.
- lane: main or background.
- `progress`: Current most reliable progress snapshot.
- `stage_detail`: Human-facing copy; not involved in logic.
- `background_stages`: Concurrent background phases, e.g., render warm-up.

## Frontend rules

- Status stuck at read stage. `display_stage + lane=main`。
- Progress bar reading `progress.unit/current/total/percent`。
- `stage_detail` Display only, not for decision.
- After page refresh, do not rely solely on events Replay: restore state from detail snapshot first.

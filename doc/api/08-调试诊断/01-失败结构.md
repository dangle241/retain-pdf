# Failure structure

On task failure, read job detail failure and diagnostics interfaces first.

## Task diagnostics

```http
GET /api/v1/jobs/{job_id}/diagnostics
```

## Failure field example

```json
{
  "failed_stage": "translation",
  "failure_code": "python_unhandled_exception",
  "failure_category": "translation",
"summary": "Task failed, but no clear root cause identified yet",
  "detail": "translation review gate blocked",
  "retryable": true,
  "provider": "translation",
  "raw_exception_type": "RuntimeError"
}
```

## Frontend rules

- Error Title First `summary`。
- Expand details to use `detail`。
- Retry button display references retryable and stage-actions.
- Do not directly display the full traceback Default shown to regular users.
- `raw_excerpt`、`traceback`Diagnose issue. payload Possibly already desensitized.

## Debug

```http
GET /api/v1/jobs/{job_id}/translation/diagnostics
GET /api/v1/jobs/{job_id}/translation/items
GET /api/v1/jobs/{job_id}/translation/items/{item_id}
POST /api/v1/jobs/{job_id}/translation/items/{item_id}/replay
```

These interfaces troubleshoot missing translations, abnormal model output, batch failures, and replayShould not be depended upon in the main user flow.

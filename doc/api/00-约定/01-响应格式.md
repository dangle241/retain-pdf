# Response format

Except for the file download API, the backend JSON All responses use a uniform wrapper object.

## Success response

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

Field description:

- `code`: Business status codes.`0` Success.
- `message`: Short messages for humans.
- `data`: Specific response body.

## Error response

```json
{
  "code": 400,
  "message": "invalid request",
  "data": null
}
```

Error responses may also include structured failure details; see Failure structure.

## File response

These APIs return file streams directly. Do not use. JSON Package:

- `GET /api/v1/jobs/{job_id}/pdf`
- `GET /api/v1/jobs/{job_id}/pdf/side-by-side`
- `GET /api/v1/jobs/{job_id}/cover`
- `GET /api/v1/jobs/{job_id}/thumbnail`
- `GET /api/v1/jobs/{job_id}/preview/pages/{page}`
- `GET /api/v1/jobs/{job_id}/markdown?raw=true`
- `GET /api/v1/jobs/{job_id}/markdown/images/{path}`
- `GET /api/v1/jobs/{job_id}/download`
- GET /api/v1/jobs/{job_id}/artifacts/{artifact_key} returns file stream if artifact is a file.

Frontend download should use HTTP status and Content-Type to determine success, not parse JSON directly.

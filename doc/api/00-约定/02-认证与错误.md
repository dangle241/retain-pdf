# Authentication and Errors

## Authentication

Except GET /health, all interfaces require request headers:

```http
X-API-Key: your-api-key
```

Authentication failure typically returns 401 or 403.

## Credential field

Task request may contain downstream. provider Credentials, for example:

- `ocr.mineru_token`
- `ocr.paddle_token`
- `translation.api_key`
- command provider's ocr.options.credential

Backend won't echo plaintext. Frontend can only via similar `*_configured` Check boolean field for configuration status.

## Error handling principles.

- HTTP status Use HTTP 400 for bad requests. Include error message. ponytail: 4xx range, add 401 for auth failures.
- job status=failed means task failed. Check logs.
- Read failure reasons first from failure or diagnostics interfaces, do not infer from stage_detail.

Common statuses:

- `400`: Invalid request parameters.
- `401`: Missing or incorrect API key。
- 404: job or artifact not found.
- `409`: Operation not allowed in current state.
- `500`: Backend internal error.

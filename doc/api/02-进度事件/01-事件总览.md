# Event Overview

## Endpoint

```http
GET /api/v1/jobs/{job_id}/events
GET /api/v1/ocr/jobs/{job_id}/events
```

Event stream displays task history, current phase, and granular progress.

## Event structure

```json
{
  "created_at": "2026-06-16T12:00:00Z",
  "seq": 1234,
  "display_stage": "translation",
  "stage": "translating",
  "substage": "translation_batches",
  "lane": "main",
  "event_type": "progress",
"stage_detail": "Translating batch 789 / 5216",
  "message": "translation batch progress",
  "progress": {
    "unit": "batch",
    "current": 789,
    "total": 5216,
    "percent": 15.1
  }
}
```

## Field description

- `seq`: Globally incrementing event sequence number. Frontend uses it to distinguish new from old events.
- `display_stage`: User-visible major stages.
- `stage`: Backend internal phase.
- `substage`: Machine-readable sub-phase.
- lane: main or background.
- `event_type`: `progress`、`stage_transition`、`artifact_published` etc.
- `progress`: Sole official progress object.
- `message` / `stage_detail`: Human copy.

## Frontend rules

- Sort by seq.
- Same. `display_stage + substage + progress.unit` Internal: prioritize latest events.
- Main state select `lane=main`。
- Background preprocessing displayed in auxiliary area, does not overwrite main stage.
- Do not use message keyword to evaluate phase.

## API endpoint

Main task event flow:

`GET /api/v1/jobs/{job_id}/events?limit=50&offset=0`

OCR Subtask event stream:

`GET /api/v1/ocr/jobs/{job_id}/events?limit=50&offset=0`

Return wrapper fixed to:

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "items": [],
    "limit": 50,
    "offset": 0
  }
}
```

Frontend read path is `data.items`, not top-level `items`。

## Current specification

/events returns the Rust canonical event:

- `stage`Public phase, frontend-facing display.
- substage: machine‑readable sub‑stage.
- `lane`：`main | background | artifact | diagnostic`。
- `event_type`：`progress | artifact | terminal | error | diagnostic`。
- `progress`Public progress object.
- `message`Human-readable logs; not for machine judgment.

Mentioned in old documentation. `progress_current` / `progress_total` / `progress_unit` Internal source field. New frontend reads first. `progress`。

# Collaboration and Boundaries

How backend collaborative development keeps structure from getting messy.

## Module responsibilities

- `routes/*`
- Only do HTTP adapter work
- `services/jobs/*`
  - Task query, display, create, resume, control.
- `job_runner/*`
  - Real execution chain
- `models/*`
- Only contain DTOs and persistence models

## Dependency direction

Default orientation:

- `routes -> services -> job_snapshot_factory / job_launcher / runtime_gateway / db`
- `job_runner -> db / config / runtime state`
- models must not reverse‑depend on routes or services

## AppState conventions

`AppState` Place only where runtime collaboration is truly needed.

- Route Entry
- Lifecycle Entry
- Runtime execution layer

If only need:

- `&Db`
- `&AppConfig`
- `&Path`
- `&RwLock<HashSet<String>>`
- `&Arc<Semaphore>`

Stop forwarding. `AppState`。

## Common anti-patterns

- In route, piece together business views
- In models, read from the file system
- In job_runner, continue to pass AppState around internally incorrectly
- Treat the file layout as a public API contract

## Stable boundary

- `provider raw`、`normalized`、`published artifact`、`download API` Four distinct boundary layers.
- `failure` Official failure source
- `runtime.stage_history` Main timeline source of truth
- `failure_diagnostic` Keep only compatible projection.

## LLM permission convention

Large models may participate in semantic layer repair but cannot take over the structural layer, layout layer, or artifact layer.

### Allowed actions

- OCR Noise Semantic Normalization
  - e.g., obvious LaTeX Misrecognition Correction
  - For example, converting `\\langlen` Such stable regularizable noise converges to a deterministic result.
- Draft and title candidates
- Lightweight Categories
  - Title / Footnote / Body text semantic judgment.
  - Whether special translation rules are required for candidate evaluation.

### Advisory-only. No direct implementation.

- Indent?
- Adjust line spacing?
- Adjust font size?
- Change paragraph layout?
- Modify overlay? / Deletion Policy

### Explicitly prohibited actions

- Modifying bbox
- Change pagination
- change the original structure
- Update task status
- Change artifact path.
- bypass deterministic rules and directly rewrite rendering input

### Implementation principles

- Large model outputs "candidate fixes".
- Deterministic rules layer takes final precedence.
- Prioritize stable rule-based content for preprocessing or normalization; do not rely on the model's on-the-fly inference.
- Structural layer, layout layer, and artifact layer must remain testable, replayable, and reproducible.

## Pre-commit check

Change to `rust_api` When applicable, at least perform the corresponding checks:

- `cargo check --quiet`
- changed presentation / query, add tests
- If runner/lifecycle is changed, add tests

# Integration & Debugging

## 1. Three most common false positives

### 1.1 Check network tab. Verify response payload. If present, check frontend parsing logic.

Use directly for now. curl Look at the raw response, don't guess first.

For example:

```bash
curl -s http://127.0.0.1:41000/api/v1/jobs/<job_id> \
  -H 'X-API-Key: your-key'
```

And:

```bash
curl -s 'http://127.0.0.1:41000/api/v1/jobs/<job_id>/events?limit=50&offset=0' \
  -H 'X-API-Key: your-key'
```

If original response has value but page does not, prioritize checking frontend unpack path.

### 1.2 Backend returned nothing. runtime.stage_history”

This sentence has two completely different situations:

First, the current task is an old historical task:

- `runtime = null`
- Indicates backend had not yet persisted runtime timeline then.

Second, current task is new but backend truly not written:

- This is the exception requiring investigation.

Don't conflate the two cases.

### 1.3 Details or download directly report old task unsupported

This is a different class of issue, do not confuse it with `runtime = null` Obfuscation.

If task still uses:

- `originPDF/jsonPDF/transPDF/typstPDF` Old directory layout
- Legacy absolute path artifact Storage

Then the current backend will reject the details directly./Download path required. Rerun command.

This is not a transient fault or front-end parsing issue; the current main chain has stopped supporting legacy task layouts.

### 1.4 Event stream empty.

Check first:

1. Whether the endpoint is `200`
2. `data.items` Is non-empty?
3. Is the frontend incorrectly reading as top-level? `items`

## 6. Document-level conclusion

If frontend only needs stable display:

- Timeline only `runtime.stage_history`
- Event stream view-only `/events`
- Execution protocol view only. `invocation`
- Normalization Overview Read-Only `normalization_summary`
- Do not backfill, do not mix, and do not infer the main timeline from the event stream.

## 7. Failure attribution now read how

On task failure, check in this order:

1. `data.failure.summary`
2. `data.failure.root_cause`
3. `data.failure.suggestion`
4. `data.failure.raw_diagnostic`
5. `data.failure.ai_diagnostic`

Judgment Principles:

- `failure` Primary True Source
- `failure.raw_diagnostic` Used to answer "What exactly is the original exception?"
- `failure.ai_diagnostic` Used to answer: "If the rule is not recognized,"AI thinks what it most likely is
- `failure_diagnostic` Just for backward compatibility with old fields. Do not treat as the source of truth.

Current backend failure diagnosis chain:

1. Python Top-level entry: output structured failure first. JSON
2. Rust Prioritize parsing this structured failure and classify.
3. If still `unknown`, then try to append AI Additional Diagnosis
4. Final results persisted to task details and event stream.

## 9. OCR Page range integration points.

`POST /api/v1/jobs` If you want to limit within OCR Page range, field position:

```json
{
  "ocr": {
    "page_ranges": "1-5"
  }
}
```

Current backend behavior:

- `ocr.page_ranges` Enters task persistence. `request_payload`
- When provider=mineru:
- source.upload_id: the uploaded PDF path is trimmed to a subset first, then that subset is uploaded
- source.source_url: the remote URL path is also passed through.
- Empty string means no page limit.

If `source.upload_id + ocr.page_ranges` has already identified consecutive paragraph groups, write to `source_pdf` page numbers follow. Final rendering PDF should only cover this subset; "whole book" should not appear. PDF result: only some pages translated inside.

If page range not effective, check these three layers first, not the frontend:

1. Check request details: whether request_payload.ocr.page_ranges is non‑empty
2. Check the database jobs.request_json to see whether $.ocr.page_ranges is non‑empty
3. Then check the provider execution logs, not the page forms first.

## 11. `math_mode` Integration testing key points

If troubleshooting "why formula blocks run slow" or "why no" placeholder”:

1. First look at request_payload.translation.math_mode
2. `placeholder` Indicates the current task is still using the old formula protection chain
3. `direct_typst` Current task: experimental formula direct-output branch.

Judgment principle:

- `placeholder` Appear below placeholder Validation, Formula Segmentation,windowed formula, belong expected.
- `direct_typst` Do not put below again placeholder Stability as the main issue; the focus should be on model output quality, English residue, and rendering compatibility

## 10. Old tasks rejected: requeue with backoff.

If detail or download API returns "old task not supported, rerun required", confirm in this order:

1. Check if the task directory is still `originPDF/jsonPDF/transPDF/typstPDF`
2. View Database artifacts Is storage still an absolute path?
3. Check if this task is earlier than this round. spec-only with new artifact Switch Layout

Conclusion:

- This type of task is not automatically migrated currently.
- Don't write temporary compatibility shims.
- Correct fix: rerun.

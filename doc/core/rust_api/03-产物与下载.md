# Artifacts and downloads

This article covers how to discover and download task artifacts.

## Artifact list

Main interface

- `GET /api/v1/jobs/{job_id}/artifacts-manifest`
- `GET /api/v1/ocr/jobs/{job_id}/artifacts-manifest`

It is the official machine discovery entry.

Common fields per item:

- `artifact_key`
- `artifact_group`
- `artifact_kind`
- `ready`
- `file_name`
- `content_type`
- `size_bytes`
- `relative_path`
- `checksum`
- `source_stage`
- `updated_at`
- `resource_path`
- `resource_url`

Recommended workflow:

1. Check first manifest
2. Find target `artifact_key`
3. Confirm ready=true
4. Then use resource_path or resource_url

## Download entry

Common download APIs:

- `/pdf`
- `/markdown`
- `/normalized-document`
- `/normalization-report`
- `/download`
- `/artifacts/{artifact_key}`
- `/preview/pages/{page}?kind=source|translated&width=1200`

Markdown Important Notes:

- /markdown returns JSON wrapper by default
- /markdown?raw=true returns raw Markdown
- `markdown_bundle_zip` Best package for frontend direct download.

Page-level preview images serve as fallback for the reader's first screen:

- Returns image/jpeg
- Use strong caching:`Cache-Control: public, max-age=31536000, immutable`
- Return stable. `ETag`
- Cached under artifacts/ per job

## Four-layer boundary

Backend externally: four layers:

- `provider raw`
- `normalized`
- `published artifact`
- `download API`

Directory structure not public contract.

## Troubleshooting entry points

If button unclickable, check:

- `actions.*.enabled`
- `artifacts.*.ready`
- `artifacts-manifest.items[].ready`

If download fails, check:

- `failure`
- `runtime`
- `log_tail`
- `/events`

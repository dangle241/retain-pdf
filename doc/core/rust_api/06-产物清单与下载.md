## 1. Audit. Traceability. Reproducibility.

The task directory is an internal backend implementation detail and may be subject to further adjustments.

Therefore, frontend or external callers should not depend on:

- `rendered/` Below what?
- What must be under md/
- `ocr/unpacked/` Never change.

The official external source is now the stable product list in the database, and then through API Expose.

## 2. Main interface

Main task:

`GET /api/v1/jobs/{job_id}/artifacts-manifest`

OCR subtask:

`GET /api/v1/ocr/jobs/{job_id}/artifacts-manifest`

## 3. What does it return

Returns the currently registered artifact entries for this task; each entry has:

- `artifact_key`
- `artifact_group`
- `artifact_kind`
- `ready`
- `file_name`
- `content_type`
- `size_bytes`
- `relative_path`
- `checksum`
- `source_stage`
- `updated_at`
- `resource_path`
- `resource_url`

What the frontend should actually use:

- `artifact_key`
- `ready`
- `resource_path` / `resource_url`

The artifacts in the detail endpoint are suitable for quick button state determination; for complete machine‑readable information, use artifacts-manifest.

## 4. Common artifact keys

Currently common include:

- `source_pdf`
  - If the request has been set `ocr.page_ranges` Local upload only. Path points to subset generated within task. PDF
- `translated_pdf`
- `typst_source`
- `typst_render_pdf`
- `markdown_raw`
- `markdown_images_dir`
- `markdown_bundle_zip`
- `normalized_document_json`
- `normalization_report_json`
- `layout_json`
- `translation_manifest_json`
- `provider_bundle_zip`
- `provider_result_json`
- `pipeline_summary`
- `events_jsonl`
  - Task runtime persisted event stream export. Debug download.

Distinguish the following semantics:

- `provider_result_json` / `provider_bundle_zip`
Belongs to provider raw
- `normalized_document_json` / `normalization_report_json`
Belongs to normalized
- `markdown_raw` / `markdown_bundle_zip` / `translated_pdf`
Belongs to published artifact

While /pdf, /normalized-document, and /artifacts/{artifact_key} belong to the download API

Compare PDF Do not require frontend local synthesis. Call directly.

- `GET /api/v1/jobs/{job_id}/pdf/side-by-side`
- Returns application/pdf
- Backend reads source. PDF and final translation PDFGenerate and cache
  `jobs/{job_id}/artifacts/{job_id}-side-by-side.pdf`
- For each page: original left, translation right. If page counts differ, output uses the larger count; missing side left blank.
- Returns 404 if the source PDF or translated PDF is not ready

## 5. Recommended read method

Frontend or scripts must no longer guess file locations from directory structure; instead:

1. Request first. `artifacts-manifest`
2. Target found `artifact_key`
3. Check ready
4. Use resource_path or resource_url

Among them, markdown_bundle_zip is the best package for frontend direct download of Markdown:

- Contains only `markdown/full.md`
- Contains only `markdown/images/**`
- Exclude original. PDF
- No translation performed. PDF
- Does not include provider bundle
- Exclude other debug info. JSON

If desired. ZIP Extracted dir includes task number; append on direct download:

`?include_job_dir=true`

At this point, the root directory defaults to `markdown/` becomes:

`{job_id}-markdown/`

If you want to download the raw event stream of the task, you can also directly query:

- `artifact_key = events_jsonl`

Its semantics are:

- Stable debug artifact
- Content from the task log directory. `events.jsonl`
- For troubleshooting, export, and archive.

Note:

- The events stream tab should still read the /events interface first
- Frontend avoid `events_jsonl` Treat as the main display interface and source of truth.

## 6. Relation to legacy API.

Old interface still retained, e.g.:

- `/pdf`
- `/markdown`
- `/normalized-document`

Internally shifting to: check artifact list first, then locate actual file.

Think of it as:

- Legacy API: stable download entry.
- `artifacts-manifest` Stable discovery entry.
- Details `artifacts.pdf` / `artifacts.markdown` / `artifacts.bundle` Recommended page status field.
- Siblings in Details `pdf_url` / `markdown_url` / `bundle_url` Old field compatibility alias only; new code must not depend on it.

Boundary condition? Specify.

- Here, 'old interface' refers to the current API Stable resource entry within
- Does not refer to legacy task directory layout compatibility.

If the task itself still comes from `originPDF/jsonPDF/transPDF/typstPDF` Legacy layout, or artifact If absolute paths are still stored, these download entry points will directly reject; must rerun.
